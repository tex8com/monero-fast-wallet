# Contributing

Please begin with a small, focused change and the README for the component you
intend to modify. Preserve upstream license notices and keep security-critical
wallet and node changes narrow and reviewable.

Before opening a pull request:

1. Use test wallets and synthetic data only.
2. Run the relevant locked test, lint and contract checks.
3. Do not add credentials, private infrastructure data, raw logs, wallet files
   or build output.
4. Describe the security impact and the validation performed.

Security issues must use the private reporting route in the root
[SECURITY.md](../SECURITY.md), not a public issue or pull request.
